# Mini ETL Pipeline: 取引データ集計

1週間のエンジニア基礎学習の集大成として作成した、ミニETLパイプラインです。
顧客・商品・取引の3つのCSVデータを読み込み、pandasで加工・集計し、結果をSQLiteに保存します。

## 概要

- **Extract**: 顧客マスタ・商品マスタ・取引データ(CSV)を読み込む
- **Transform**: pandasでJOIN・集約を行い、2種類の集計を算出する
- **Load**: 集計結果をSQLiteデータベースに保存する

## データ構成

ファクトテーブルとディメンションテーブルに分けて設計しました。

### ファクトテーブル(取引データ)
| カラム | 説明 |
|---|---|
| 取引id | 1回の購買を識別するID(同一取引idは同じ買い物とみなす) |
| 顧客id | 顧客マスタへの外部キー |
| 商品id | 商品マスタへの外部キー |
| 個数 | 購入個数 |
| 合計金額 | その商品の小計金額 |
| 取引日時 | 購入日時 |

### ディメンションテーブル(顧客マスタ)
| カラム | 説明 |
|---|---|
| 顧客id | 主キー |
| 年齢 | - |
| 性別 | - |
| 会員登録日 | - |

### ディメンションテーブル(商品マスタ)
| カラム | 説明 |
|---|---|
| 商品id | 主キー |
| 商品名 | - |
| カテゴリ | - |
| 値段 | 商品マスタ上の定価(取引時点の実売価格とは区別) |

## 処理内容(Transform)

2つの集計を行っています。どちらも「取引単位で一度集約してから、別の軸で再集約する」という2段階の集約構造になっている点が今回のポイントです。

### 1. 年代別の購買単価(`aggregate_by_age`)
1回の取引(取引id単位)における合計金額を算出し、顧客の年代(10歳区切り)ごとに平均を算出します。

処理の流れ:
1. 取引データと顧客マスタをJOIN
2. 取引id単位で合計金額を集約(同一取引の複数商品分を合算)
3. 年代(age_bin)ごとに平均金額を算出

### 2. カテゴリ別の購買個数傾向(`aggregate_by_category`)
1回の取引で、あるカテゴリの商品を平均何個買うかを算出します。

処理の流れ:
1. 取引データと商品マスタをJOIN
2. 取引id×カテゴリ単位で個数を集約
3. カテゴリごとに平均個数を算出

## 設計上の工夫

- **クラス設計**: `Transaction_Aggregate`クラスに、読み込み(`load_data`)・集計(`aggregate_by_age`, `aggregate_by_category`)・保存(`save_to_db`)を責務ごとに分離。共通処理(CSV読み込み)を1箇所にまとめ、重複を避けています。
- **テスト**: 2つの集計ロジックそれぞれに対し、意図的に「同一取引idで複数商品を購入するケース」を含めたテストデータを用意し、期待値を手計算した上で`pandas.testing.assert_frame_equal`で検証しています。
